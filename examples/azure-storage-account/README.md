# Azure Storage Account Golden Path (Infrastructure-only)

This example provisions Azure infrastructure only. It does not build or deploy an application.

## Flow

Port self-service request -> GitHub Actions -> Terraform validation/plan -> protected GitHub Environment approval -> apply -> Azure Storage Account.

## Setup

1. Create an app repository from this template, or copy this example's `terraform/` directory and workflow.
2. Configure GitHub Actions secrets: `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`.
3. Configure Actions variables: `TF_STATE_RESOURCE_GROUP`, `TF_STATE_STORAGE_ACCOUNT`, `TF_STATE_CONTAINER`.
4. Create a pre-existing Azure Storage Account/container exclusively for Terraform state. It must not be the account being provisioned. Grant the service principal Storage Blob Data Contributor on the state container and appropriate resource creation permissions in the target scope.
5. Create GitHub Environments named `dev`, `staging`, and `prod`. Add required reviewers to `prod` (and staging if desired). Add the Azure secrets/variables to each environment or at repository level.
6. Configure Port to dispatch the `Provision Azure Storage Account` workflow in this repository and map form fields to the workflow inputs. The current workflow can also be run manually from Actions to test the infrastructure path before connecting Port.

## Input rules

- Storage account name: 3-24 lowercase letters and digits, globally unique.
- Region: eastus or centralus.
- Environment: dev, staging, prod.
- Replication: LRS, ZRS, GRS.

## Notes

- The apply job downloads and applies the exact plan artifact generated by the plan job.
- GitHub Environment protection must be configured in repository settings; the YAML alone does not create reviewers.
- The service principal uses a client secret for this lab. Store it only in GitHub Secrets, never in Port form fields or source control.
- This is a lab baseline, not a production-ready landing zone. Review policies, networking, private endpoints, diagnostic settings, naming/tagging standards, RBAC, and costs before production use.
